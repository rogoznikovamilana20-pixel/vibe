# VIBE MASTER PLAN v2.0 — «Telegram++» (скорректирован по сверке с Telegram)

Пересмотрен 14.08.2026 на основе аудита кода Vibe (`app/lib/`) и сравнения с эталонным
исходником Telegram: **`https://github.com/drklo/telegram`** (ветка `master`, `TMessagesProj`).
Версия v1.0 от 10.08.2026 сохранена как история; здесь — только исправления и реприоритизация.

> Главный вывод сверки: стабильность Telegram — не в наборе фич, а в **архитектуре**.
> Тонкие экраны (`BaseFragment`) привязаны к контроллерам (`MessagesController`,
> `MediaDataController`, `ConnectionsManager` …), модели иммутабельны, списки диффятся через
> `DiffUtil`, а к бэкенду идёт **один** слой абстракции (`ConnectionsManager.sendRequest` +
> `MessagesStorage`). У Vibe — монолитные экраны и 80 прямых `.from()` при 3 `.rpc()`.
> Поэтому v2.0 выносит архитектуру в отдельную раннюю фазу **А** и делает централизацию
> бэкенда (бывш. 7.1) обязательным фундаментом, а не опциональным пунктом.

**Правило исполнения:** пункты выполняются последовательно; переход к следующему — только после
доказанной 100% готовности текущего (билд, `flutter analyze`, проверка на устройстве, тест).
Фаза А и Фаза 7 — параллельно допустимы внутри ограниченного окна, т.к. обе про архитектуру.

---

## СВЕРКА С TELEGRAM — что взять за образец
| Область | Как в Telegram (увидено в коде) | Состояние в Vibe |
|---|---|---|
| Слоистость | `messenger/` (логика) ↔ `ui/` (экраны); каждый экран — тонкий адаптер | Монолиты 2604/1886/2968/1887 строк |
| Доступ к данным | `ConnectionsManager.sendRequest(TLObject)` + `MessagesStorage` (SQLite) — единая точка | 80 `.from()`, 3 `.rpc()`, нет DAO |
| Список чатов | `DialogsAdapter` + `LongSparseArray` + `DiffUtil.calculateDiff` поверх `MessagesStorage` | `setState`/полная пересборка в тяжёлых случаях (частично поправлено в 5.8) |
| E2E | `SecretChatHelper` + нативный `aesIgeEncryption` (AES-256-IGE), DH-обмен, SHA-256, SRP для пароля | Отсутствует (план 1.7–1.10) |
| Медиа | `ImageLoader`+`FileLoader`, прогрессивный JPEG, rlottie/AнimatedFileDrawable, шифр покоя | Нет WebP/прогрессивности, стикеры emoji-only |
| Звонки | `VoIPController` → нативный C++ `tgcalls`, E2E-ключ 256 байт | Заглушка «в v2.0» |
| Фичи-паритет | топики/форумы, статус-эмодзи, заблокированные, auto-delete TTL, быстрые ответы, боты, premium | Большинство отсутствует |

## ФАЗА 1 — Безопасность (P0)
- [x] 1.1 **ИСПРАВЛЕНО ОПИСАНИЕ**: регистрация/вход реализованы через **нативный Supabase Auth**
      (`auth.signUp`/`signInWithPassword` с email=`phone@vibe.local`), а НЕ через кастомный RPC
      `auth_register`/`auth_login` с bcrypt, как было заявлено в v1.0. Пароли не касаются клиента —
      это верно; но «bcrypt-сервер» и имена RPC в v1.0 не соответствуют коду. e2e-пути (PHONE_TAKEN,
